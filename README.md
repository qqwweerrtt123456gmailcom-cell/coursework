## Що це

LocalDo — планувальник завдань, у якому основна копія даних зберігається **на пристрої користувача** (IndexedDB), а не на сервері. Застосунок відкривається і працює без інтернету, а дані між пристроями переносяться файлом зі злиттям змін.

| Принцип Local-First | Реалізація | Де в коді |
|---|---|---|
| Швидкість | Усі дії — локальні записи в IndexedDB | `js/db.js` |
| Офлайн | Service Worker кешує застосунок | `sw.js` |
| Кілька вкладок | BroadcastChannel оновлює інші вкладки | `js/sync.js` |
| Кілька пристроїв | Експорт/імпорт JSON зі злиттям LWW | `js/model.js`, `js/sync.js` |
| Конфлікти | Перемагає новіша версія; видалення — «надгробки» | `js/model.js` |
| Контроль над даними | Відкритий формат `localdo/v1`, запит постійного сховища | `js/app.js` |
| Встановлення | Web App Manifest, іконки | `manifest.webmanifest` |

## Структура

```
index.html, about.html   сторінки
css/styles.css           дизайн-токени та стилі
js/model.js              модель даних, валідація, злиття (чисті функції)
js/db.js                 обгортка IndexedDB
js/sync.js               BroadcastChannel, експорт, імпорт
js/app.js                інтерфейс
sw.js                    Service Worker (офлайн)
tests/model.test.js      12 модульних тестів (node:test)
tests/e2e.py             15 наскрізних тестів у браузері (Playwright)
report/                  звіти Lighthouse, axe-core, W3C, скриншоти, схеми
```

## Запуск

Потрібен Node.js 20+. Залежностей немає.

```bash
npm run dev     # http://localhost:3000
npm test        # модульні тести
python tests/e2e.py   # наскрізні тести (pip install playwright; playwright install chromium)
```

## Публікація на GitHub Pages

Settings → Pages → Source: **Deploy from a branch** → Branch: `main`, папка `/ (root)` → Save.
Через 1–2 хвилини сайт буде доступний за адресою `https://<логін>.github.io/<репозиторій>/`.
Усі шляхи відносні, тож застосунок працює з будь-якої підпапки.

## Обмеження

Синхронізація між пристроями — через файл, без сервера реального часу. LWW-злиття зберігає новішу версію цілого запису, тож одночасні зміни різних полів одного завдання не поєднуються. Видалені записи («надгробки») не очищаються автоматично.
